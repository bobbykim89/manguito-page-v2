# Agentic Tooling, Node 24 and PR CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give manguito-page-v2 the same agent context, toolchain, lint/format/test setup, PR CI and branch protection as mango-planner-v2, with no change to how the site behaves.

**Architecture:** Copy mango-planner-v2's config files and adapt them. The one production code change is an optional `mongoUri` override for the DB connection, so an API test harness (Nuxt production build run against `mongodb-memory-server`) can work. A second Vitest project runs client unit tests in the Nuxt environment.

**Tech Stack:** Node 24, pnpm 12 (corepack), Nuxt 4.3, ESLint 10 flat config + typescript-eslint + eslint-plugin-vue, Prettier 3 + prettier-plugin-tailwindcss, Vitest + @nuxt/test-utils + happy-dom, mongodb-memory-server, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-17-agentic-tooling-ci-design.md` (issue #11). Read it first.

**Reference repo:** `/mnt/projects/mango-planner-v2` (abbreviated `MP/` below). "Copy" means copy the file and then make only the adaptations listed.

## Global Constraints

- Branch: `feat/11-agentic-tooling-ci` (already exists; the spec is committed on it).
- Node: `.nvmrc` = `24`; `engines.node` = `>=24.0.0`.
- pnpm: latest stable 12.x (12.21.0 at time of writing), pinned in `packageManager` with its sha512 via `corepack use pnpm@<version>`.
- No bumps to existing dependencies. Exception: when a new dev tool's peer range rejects the current Nuxt 4.3 / Vite 7, bump only what's needed and list it in the PR description. Otherwise prefer MP's dev-dependency versions, falling back to the newest version compatible with Vite 7.
- Never read, print or edit `.env` or `.env.*`. Never run `dev:prod`, `dev:dev`, `build`, `build:prod` or `build:dev`; use `pnpm dev` / `pnpm build:local` only.
- Production code changes are limited to: the 13 lint fixes (Task 2), the Prettier reformat (Task 3), and the `mongoUri` override (Task 4). Each must leave runtime behaviour identical.
- Lint rules are never relaxed or disabled to get to green.
- Commit messages: Conventional Commits with a path scope, matching repo history, e.g. `chore(package.json): ...`, `feat(test/): ...`. Each ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- No rebasing after Task 3's commit hash is recorded.

## Review Focus

1. **Tests picking up the developer's real `.env`.** Nuxt loads `.env` by default, including in the unit environment. Expected: both test projects see only `test/test.env` values. Pinned by `test/unit/env.test.ts` (Task 4).
2. **DB override leaking into production.** With `mongoUri` empty, the URL must be byte-for-byte what `connectDb.ts` builds today, for both `LOCAL` and Atlas. Pinned by `test/unit/mongoUrl.test.ts` (Task 4).
3. **The Prettier commit changing behaviour** (Vue template whitespace, class order affecting cascade). Expected: identical rendering. Covered by the full test suite plus a manual `pnpm dev` click-through in Task 3.
4. **Required check names not matching job names**, which would leave every PR waiting forever. Expected: `gh pr checks` shows `lint` and `test` before protection is applied (Task 7).
5. **Vercel building with the wrong pnpm.** Expected: the preview build log shows pnpm 12 and the preview site works (Task 7, owner step).
