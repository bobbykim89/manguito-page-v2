# Manguito Page v2

Photo blog for Manguito, a peach-faced lovebird. Nuxt 4 (Vue 3) frontend and a Nitro/H3 API in one repo, with MongoDB via Mongoose. Images are hosted on Cloudinary, password-reset emails go out through Nodemailer (Gmail), and client state lives in Pinia. Features: a photo grid and post pages with comments, JWT auth with signup, login and email password reset, and an admin area (posts, comments, users, access requests). Installable PWA. Deployed on Vercel (https://manguito-page.bobbykim.dev/).

Current focus: the improvement backlog in GitHub issues #11–#22 (tooling, component-library upgrade, dependency bumps, backend refactor, stores refactor, infinite scroll, image uploads, hydration, accessibility, About page, dashboard). Prefer small, verifiable changes over sweeping rewrites. When an issue changes a convention below (e.g. #16 stores), update this file in the same PR.

## Toolchain

- Node **24** (`.nvmrc`; run `nvm use` first). `engines.node` is `>=24.0.0`.
- pnpm **12** pinned via `packageManager` (use corepack). Build scripts must be explicitly allowed in `pnpm-workspace.yaml` under `allowBuilds`; pnpm 12 fails the install on unapproved ones.
- Vercel uses the pinned pnpm because the project sets `ENABLE_EXPERIMENTAL_COREPACK=1`.
- Held back on purpose: TypeScript stays on 6.0 (7.0 is the native compiler, which `vue-tsc` doesn't support yet) and `@types/node` on 24 (the runtime is Node 24). Tailwind 4 runs through its Vite plugin (`@tailwindcss/vite` in `nuxt.config.ts`), not PostCSS.

**Tests:** Vitest runs two projects (`vitest.config.ts`):

- `api`: `test/api/` and `test/pages/`. The global setup (`test/setup/global.ts`) builds the app with the fake values in `test/test.env` (never the real `.env`), starts it against `mongodb-memory-server` (via `NUXT_MONGO_URI`, see `server/utils/mongoUrl.util.ts`) with require-of-ESM disabled (like Vercel), and the tests call the real `/api` routes (`test/utils/api.ts`) and render real pages. `test/utils/db.ts` connects to the same memory DB for setup and assertions. Set `SKIP_BUILD=1` to reuse an existing `.output` when only tests changed. Mail and Cloudinary never leave the machine: `test/setup/fakes.ts` runs a local SMTP sink (`NUXT_MAILER_*`) and a fake Cloudinary API (`CLOUDINARY_URL` with `upload_prefix`), and tests read what they received with `sentMail()` / `cloudinaryCalls()` from `test/utils/fakes.ts` (call `resetFakes()` first); `failNext('mail' | 'cloudinary')` makes the next call fail. Assert errors with `expectApiError(res, code, message?)` (`test/utils/api.ts`); `signup()` (`test/utils/auth.ts`) makes a real user with a known password.
- `unit`: `test/unit/`, client stores, composables and pure server helpers in the Nuxt environment (happy-dom), loading `test/test.env`. Call `resetState()` from `test/unit/helpers.ts` in `beforeEach`; mock API routes with `mockApi(method, url, handler)`, answering `okEnvelope(data)` or `failEnvelope(event, code, message)`, and remove them with `clearApiMocks()` in `afterEach`. Set a session by patching `userStore.currentUser` (the other auth fields are derived). Stores mounted pages read live in `useNuxtApp().$pinia`, not the one `resetState()` activates. After adding a composable, clear `node_modules/.cache/nuxt` and `node_modules/.vitest-cache`, or the unit project won't auto-import it.

CI (`.github/workflows/ci.yml`) runs two jobs on every PR: `lint` (`pnpm lint`, `pnpm format:check`) and `test` (`pnpm typecheck`, `pnpm test`). Both are required checks on `master`. Run `pnpm lint` and `pnpm format` before committing; also exercise UI changes in `pnpm dev`.

## Conventions

- **API routes are thin.** Each `server/api/**/<name>.<method>.ts` only wires middleware and a controller method:
  ```ts
  export default defineApiRoute({
    middleware: [checkAuth],
    handler: postController.updatePost,
  })
  ```
  `defineApiRoute` (`server/utils/defineApiRoute.util.ts`) runs each middleware (plain `(e) => void` functions that throw to refuse), then the handler, and answers `{ ok: true, data }` (status 200, or `status: 201` on creates) or the error envelope. Unknown `/api` paths and methods hit `server/api/[...].ts` (404 `NOT_FOUND`). Logic lives in class-based controllers (`server/controller/<domain>/<domain>.controller.ts`), exported as singletons from `server/controller/index.ts`. A new post's middleware runs `requireRole(...)` (`server/utils/requireRole.util.ts`), then `readFormDataText`, then `uploadCloudinary`, so a refused or incomplete request never reaches Cloudinary. Check route param and body ids with `parseObjectId(...)` before querying.
- **Validation:** request bodies go through Zod schemas in `shared/dto/<domain>/` via `readValidatedBody(e, schema.parse)`. A failure answers 400 `VALIDATION_FAILED` with one `details` entry (`{ path, message }`) per invalid field. Length limits and their messages live in `shared/dto/limits.ts` (`LIMITS`, `LIMIT_MESSAGES`, and the trimmed `emailSchema`, `captionSchema`, `commentTextSchema`, `usernameSchema`); the schemas mirror them as `maxlength`, and the client forms import the same constants. Emails are trimmed and lowercased, so lookups ignore case; usernames are unique as typed.
- **Database:** indexes are declared on the Mongoose schemas and built by `autoIndex` once a request has loaded the models (unique `email`, `name` and `tokens.userId`; `posts.date`; `comments.post`). Before adding a unique index, run `scripts/check-db.ts` against the remote databases. Use `.lean()` only where no returned field (populated ones included) has a schema default: production has old users without `role`/`updatedAt` and posts without `updatedAt`, which only hydrated documents fill in.
- **Errors:** every `/api` response is `{ ok: true, data }` or `{ ok: false, error: { code, message, details? } }` (types and `API_ERROR_STATUS` in `shared/types/api.types.ts`). Throw `apiError(code, message)` (`server/utils/apiError.util.ts`); `message` is shown to users, so write a sentence and never include internals. Codes: `VALIDATION_FAILED` 400 (bad body, bad id, missing field), `UNAUTHENTICATED` 401 (no, bad or dead session), `INVALID_CREDENTIALS` 401 (wrong login or current password), `FORBIDDEN` 403 (role or ownership refusal), `NOT_FOUND` 404, `CONFLICT` 409 (taken email or name), `UNSUPPORTED_MEDIA_TYPE` 415, `UPSTREAM_FAILED` 502 (Cloudinary, mail), `INTERNAL` 500. Anything else thrown is logged and answered `INTERNAL` with a generic message (`toApiFailure`). On the client, call the API with `useNuxtApp().$api` (adds the token, unwraps `data`, throws `ApiError` with `status`, `code`, `details`) or `useApi` (`useFetch` through the same instance; its error is a `NuxtError` whose `.data` is the envelope, since the class doesn't survive the SSR payload). `useErrorCheck().extractMessage` reads either (a `VALIDATION_FAILED` with exactly one `details` entry gives that entry's message); `isAuthError` is true only for code `UNAUTHENTICATED`, never by status. Run every API action through `useApiAction().run(() => $api(...), { success?, quiet? })`: it shows the success alert, or on failure ends a dead session (`userStore.expireSession()`) and alerts the message, and resolves `{ ok: true, data }` or `{ ok: false }` without throwing. A caller's own `onRequest`/`onResponse` on `$api` run after the plugin's token and unwrapping. `app/error.vue` shows the real status: 404 says the page doesn't exist, other 4xx show `statusMessage`, 5xx show a generic message (never server internals).
- **Auth:** `POST /api/auth` (and signup) return `data: { accessToken: "Bearer <jwt>" }`. The client stores it in the `access_token` cookie (`useAuthToken`, 7 days) and sends it verbatim as the `Authorization` header. `server/utils/checkAuth.util.ts` (async) verifies it, sets `event.context.user`, and loads the user through the per-request DataLoader (`server/utils/userLoader.util.ts`). Controllers and `requireRole` get the user with `getCurrentUser(e)` (hydrated, no password), never their own `findById`, so a request reads its user once; after changing the user, use what the write returned. A valid token whose user no longer exists gets **401** `UNAUTHENTICATED`, `Session expired, please log in again` (not 404). Tokens are signed by `signSessionToken(user)` with `{ id, v: tokenVersion }`; an email password reset bumps `tokenVersion`, which logs out every device (same 401), while a settings password change doesn't. A missing `v` or `tokenVersion` counts as 0. The user schema's `toJSON` drops `password` and `tokenVersion`. `useAuthToken` returns one shared cookie ref per app instance. Roles are `ADMIN`, `MANAGER`, `USER`; role checks live in each controller method.
- **Client state:** Pinia setup stores in `app/stores/` hold only state several pages share: `userStore` (the session: `currentUser`, `sessionExpired`; getters `isAuthenticated`, `role`, `isAdmin`, `isManagerOrUp` derived from `currentUser`), `postStore` (the post list and its create/update/delete) and `alertStore`. Store actions are "run the call, update state"; they don't repeat the server's permission rules. `app/plugins/init.plugin.ts` (`dependsOn: ['api']`) runs `postStore.getAllPosts()` and `userStore.ensureAuth()` concurrently on `app:created`; `ensureAuth` is the current-user check, at most once per app instance. An `UNAUTHENTICATED` error from any action logs out through `userStore.expireSession()`: **quietly** for the startup check, with the message for actions the user started. `sessionExpired` is set only when a held session is rejected, and logout, login and signup clear it. `FORBIDDEN`, `INVALID_CREDENTIALS` and other errors only alert. The route guards (`adminRoute`, `authRoute`, `guestRoute`) `await userStore.ensureAuth()` first, so they also run during the server render; on a protected page an expired session goes to `/auth/login?reason=expired` (the login page explains it), no session goes to `/` (the guard's alert shows only on client-side navigation; on a first-load 302 it's lost).
- **Client layout:** `app/stores/<thing>Store.ts` exports `use<Thing>Store`, for shared state only. `app/composables/use<Thing>.ts` holds functions that need the Nuxt context: the API client (`useApi`, built with `createUseFetch` so each call site gets its own key; `useApiAction`; `useErrorCheck`; `useAuthToken`), page data (`usePostNavigation` for the open post and prev/next, `usePostComments`, `useAccountSettings` for the layouts' account forms) and `useImageUrl.ts`, the one class among them (`ImageUrl`, which reads the runtime config). A page keeps its own data inline when it's one list and an action or two (the admin pages); it moves to a composable when it carries logic worth testing or two places share it. `app/utils/` holds pure functions and classes with no Nuxt context (`apiError.ts`, `passwordRule.ts`). Never resolve a store after an `await`: in SSR it could belong to another request.
- **Component library** (`@bobbykim/manguito-theme` 1.x, `mcl-*`): open `Modal`/`Sidebar` through their template ref (`open()`/`close()`), and build collapsibles from `Collapse` in an `<AccordionGroup>` with `useCollapseTrigger` (from `@bobbykim/manguito-theme/composable`) on the trigger button. `v-toggle`/`v-collapse` don't work. Use the 1.x prop names (`custom-class`, `show-*`, `MclFormGroup`'s `field-id`); Vue passes unknown props through silently, so `test/unit/libraryMigration.test.ts` bans the old ones. Show form errors by binding `:invalid` (with `invalid-feedback`); native validity no longer shows them. The theme's background utility is `mcl-bg-*`, so fade a color with Tailwind's `bg-<color>/<opacity>`, not `bg-opacity-*`. The theme's spacing tokens (`--spacing-xs` … `--spacing-3xl`) also win over Tailwind's container sizes, so `max-w-md` is 2rem, not 28rem: write the width out (`max-w-[28rem]`). `isomorphic-dompurify`'s jsdom is pinned to 25 in `pnpm-workspace.yaml` because newer jsdom breaks SSR on Vercel; keep the pin.
- **Browser-only APIs** (window, image compression) are guarded with `import.meta.client` or `<ClientOnly>` to avoid SSR/hydration errors.
- **Style:** Prettier (single quotes, no semicolons, 2-space indent, Tailwind classes sorted by `prettier-plugin-tailwindcss`), checked in CI. TypeScript strict. A deliberately unused binding starts with `_`. Match the surrounding code.

## Guardrails

- Do **not** read, print, or edit `.env` / `.env.*`. If you need to know which variables exist, look at `runtimeConfig` in `nuxt.config.ts`; `test/test.env` lists them with fake values.
- `pnpm dev:dev`, `dev:prod`, `build`, `build:dev` and `build:prod` point at remote services with real data. Don't run anything that writes data against them without asking. Use `pnpm dev` / `build:local` with the local DB.
- `master` is protected: work on a branch and open a PR; `lint` and `test` must pass. PRs are merged with merge commits (keeps `.git-blame-ignore-revs` hashes valid). Commit messages follow Conventional Commits with a path scope, e.g. `fix(server/controller/): ...`, `feat(app/stores/): ...`.
